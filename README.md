# ⚡ VoltAgent — بيئة بحثية لدعم المولد عبر بطارية

**الحالة الحالية: نموذج بحثي يعمل بالمحاكاة فقط. لا يتصل بمولد أو إنفرتر أو بطارية حقيقية.**

VoltAgent مشروع تجريبي لدراسة استخدام PPO في دعم تردد مولد افتراضي عبر تيار بطارية ثنائي الاتجاه، مع تقليل إجهاد البطارية في نموذج محاكاة مبسط.

> **تنبيه هندسي:** قيم القدرة والجهد والتيار ومعاملات القصور واستجابة الحاكم والحرارة في البيئة الحالية افتراضات تعليمية قابلة للتغيير، وليست مواصفات معدات أو حدود حماية معتمدة. لا تستخدم النموذج للتحكم في معدات فعلية أو لاتخاذ قرارات سلامة كهربائية.

## ما الذي تم إصلاحه؟

- إعادة بناء بيئة المحاكاة لتكون أوضح، قابلة لإعادة الإنتاج، وتستخدم معادلات مبسطة لكنها أكثر اتساقًا من النسخة السابقة.
- جعل الملاحظات تشمل التردد ومعدل تغيره وتيار البطارية الموقّع وحرارتها وحالة الشحن SOC والحمل والقدرة الميكانيكية الافتراضية.
- تمثيل التفريغ لدعم حمل المولد والشحن لامتصاص فائض القدرة، مع قيود SOC ودرجة الحرارة وتكلفة لاستخدام البطارية في المكافأة.
- رفع مخطط النموذج إلى `research-v3`؛ النماذج السابقة غير متوافقة وتحتاج إلى تدريب جديد.
- فصل سجلات النسخة القديمة عن سجلات المحاكاة الجديدة.
- إزالة التحديث التلقائي للنموذج من ملف CSV. النسخة الحالية لا تدعي وجود مسار تعلم مستمر من بيانات ميدانية.
- إضافة بيانات وصفية للنموذج بعد التدريب، وفحص توافقها عند الاستدلال.
- إضافة اختبارات أساسية وتقرير مراجعة هندسية.
- تحويل `requirements.txt` إلى UTF-8 مع تحديد المتطلبات المباشرة بدل قائمة طويلة من التبعيات العابرة.

## هيكل المشروع


## الإعداد على Windows

استخدم Python 3.10 أو أحدث؛ يعتمد إعداد الحزم على Stable-Baselines3 2.9.x وGymnasium 1.3 أو أحدث ضمن السلاسل المحددة في `requirements.txt`.

افتح PowerShell داخل مجلد المشروع ونفّذ:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
```

إذا منع PowerShell تفعيل البيئة بسبب سياسة التنفيذ، افتح موجه الأوامر `cmd` واستخدم:

```bat
.venv\Scripts\activate.bat
```

## التدريب

```powershell
python train_agent.py
```

لتغيير عدد خطوات التدريب والبذرة العشوائية:

```powershell
python train_agent.py --timesteps 50000 --seed 42 --eval-episodes 8
```

يحفظ التدريب نموذجًا جديدًا باسم `inverter_agent_ppo.zip` وملف بيانات وصفية `inverter_agent_ppo.metadata.json`، كما يكتب تقرير تقييم للمحاكاة داخل `reports/`.

**لا يعاد استخدام النموذج القديم تلقائيًا.** النموذج المحفوظ في `legacy/` يخص مخطط ملاحظات قديمًا ولم يُثبت أداؤه.

لمتابعة تدريب نموذج v3 على rollouts جديدة من المحاكاة، احفظ مرشحًا منفصلًا ثم قيّمه قبل اعتماده:

```powershell
python train_agent.py --resume-from inverter_agent_ppo_v3 --model-path inverter_agent_ppo_v3_candidate --timesteps 50000 --seed 43 --eval-episodes 8
python compare_controllers.py --model-path inverter_agent_ppo_v3_candidate --episodes 30 --seed 5000 --output reports/controller_comparison_candidate.json
```

يتحقق التدريب المستمر من مخطط النموذج ومصدره، ولا يستبدل checkpoint المصدر. هذا تدريب دوري غير متصل ببيانات اصطناعية جديدة؛ لا يتعلم أثناء الاستدلال ولا يدرّب من CSV أو من بيانات معدات فعلية.

يمكن إجراء تجربة مقارنة لوزن استخدام البطارية مع حفظه ضمن إعدادات النموذج:

```powershell
python train_agent.py --resume-from inverter_agent_ppo_v3 --model-path inverter_agent_ppo_v3_low_battery_cost --battery-current-penalty 0.001 --timesteps 10000 --seed 43 --eval-episodes 8
python compare_controllers.py --model-path inverter_agent_ppo_v3_low_battery_cost --episodes 30 --seed 5000 --output reports/controller_comparison_low_battery_cost.json
```

## اختبار النموذج

بعد إكمال التدريب:

```powershell
python inference.py --steps 100 --seed 7
```

خيارات إضافية:

```powershell
python inference.py --steps 100 --render
python inference.py --steps 100 --no-log
python inference.py --model-path inverter_agent_ppo --log-path data/simulation_inference.csv
```

تُوسم السجلات الجديدة بوضوح على أنها `simulation`. لا تستخدمها باعتبارها قياسات ميدانية أو لتحديث النموذج تلقائيًا.

## مقارنة الوكيل بخطوط أساس

بعد تدريب نموذج جديد، قارن PPO بخط أساس لا يستخدم البطارية، وبقواعد دعم تراعي التردد أو إجهاد البطارية:

```powershell
python compare_controllers.py --episodes 30 --seed 5000
```

يستخدم البرنامج نفس بذور السيناريوهات لكل السياسات، ويصدر تقرير JSON داخل `reports/`. المتحكم `thermal_aware` قاعدة ثابتة للمقارنة وليست وكيلًا متعلمًا. لا تعني نتيجة أفضل في المحاكاة تفوقًا على معدات حقيقية.

## تشغيل الاختبارات

```powershell
pytest -q
```

الاختبارات تتحقق من عقد البيئة وتكرار إعادة التهيئة وحدود التيار واتجاه تدفق القدرة وتحديث SOC وسلوك الحارس وتسجيل مصدر البيانات. نجاحها لا يثبت صحة النموذج الفيزيائي أو سلامة تشغيل معدات حقيقية.

## ما الذي تمثله المحاكاة؟

تتضمن البيئة حاليًا:

1. نموذجًا مبسطًا لاستجابة الحاكم وقدرة المحرك الميكانيكية.
2. معادلة تقريبية من نمط معادلة التأرجح لوصف تغير التردد مع اختلال القدرة.
3. تحويلًا افتراضيًا للقدرة: التيار الموجب يفرّغ البطارية لتقليل حمل المولد، والسالب يشحنها لامتصاص الفائض.
4. تقديرًا مبسطًا لتغير SOC وخسائر الكفاءة، ونموذجًا حراريًا أحادي العقدة يعتمد على `I²R`.
5. حدود تيار ومعدل تغيير وقيودًا بحثية قرب SOC ودرجة الحرارة المنخفضة/المرتفعة.

هذا نموذج أولي لتجارب البرمجيات فقط؛ فهو لا يمثل بعد تفاصيل الجهد المتناوب أو معامل القدرة أو القدرة غير الفعالة أو حلقات تحكم الإنفرتر أو نظام BMS أو الكيمياء الكهروكيميائية أو خصائص المحرك الفعلية.

## الخطوات البحثية التالية

- تشغيل الاختبارات والتأكد من إمكان إعادة النتائج ببذرة ثابتة.
- مقارنة PPO بخط أساس لا يستخدم البطارية وبسياسات دعم ثابتة.
- تقييم عدة سيناريوهات حمل وSOC وحرارة، وقياس انحراف التردد وحرارة البطارية وSOC واستهلاك التيار وعدد حالات الإيقاف الافتراضية.
- معايرة النموذج بعد اختيار المعدات وتوفر بيانات موثوقة.
- عند توفر المعدات، البدء بقراءة القياسات في وضع المراقبة فقط، ثم تنفيذ مراجعة سلامة مستقلة قبل أي اختبار تحكم فعلي.

راجع `docs/ENGINEERING_REVIEW.md` لتفاصيل العيوب التي وجدت في النسخة الأصلية والإجراءات التي اتخذت.
